\section{Reported ``Fixed'' --- still present}
Each was marked Fixed; each still reproduces.
\begin{itemize}
  \item \textbf{\wc{084} (S1).} The note claims a centre check ``via \texttt{user\_can\_access\_centre}.''
        That function does not exist in \texttt{batch\_management.py}; \texttt{close\_batch} still saves
        with \texttt{ignore\_permissions=True} and no check. Runtime: a Skilling Partner permitted only
        for East and West closed a North batch (``Batch closed successfully''). Severity S1 stands.
  \item \textbf{\wc{128}.} The note says the production build strips console output. The deployed
        \texttt{/auth/} bundle still contains \texttt{console.log("OTP Generation Response: ", ...)} and
        logs the reset email and OTP. The strip applies to OC, not to the auth app where the reset flow runs.
  \item \textbf{\wc{126}.} Runtime: every status transition is accepted --- Skilling Invoice 30 of 30,
        Skilling Batch 72 of 72. No state machine.
  \item \textbf{\wc{123}.} Runtime: an account wrote a field on another user's record (HTTP 200).
        \texttt{update\_profile} has no active permission check.
  \item \textbf{\wc{078}.} \texttt{delete\_file\_by\_url} resolves a file by URL and deletes it with no
        owner or permission check.
  \item \textbf{\wc{080}.} \texttt{move\_youth} creates a batch-transfer approval with no caller check.
  \item \textbf{\wc{077}.} The unauthenticated endpoint still carries \texttt{allow\_guest} and assigns
        \texttt{System Manager}.
  \item \textbf{\wc{088}.} The \texttt{id = json.loads(id)} typo is still at both sites.
  \item \textbf{\wc{089} / \wc{101}.} Runtime: endpoints return HTTP 500 on malformed input instead of
        400; \texttt{add\_remarks} raises a \texttt{TypeError}.
  \item \textbf{\wc{074}.} Runtime: \texttt{close\_batch} returns HTTP 200 on a failed call.
  \item \textbf{\wc{043}.} The null-navigation crash persists; only two of nine apps define an error
        boundary to contain it.
\end{itemize}

\section{``Not a Bug'' --- disputed}
Conceded reclassifications are in section 4. The following are security-relevant and remain present.
\begin{itemize}
  \item \textbf{\wc{115}.} Marked both ``Valid Bug'' and ``Not a Bug''. \texttt{sync\_to\_lcf\_mastersheet}
        still has no authorisation check; any authenticated account, including an external Skilling
        Partner, can export programme data to an external spreadsheet. OWASP API6.
  \item \textbf{\wc{079} / \wc{073} / \wc{035}.} The permission model still does not exist as designed;
        326 \texttt{ignore\_permissions} sites bypass authorisation. This is the root cause behind the
        cross-centre write breaches (\wc{084}, and the residual in \wc{095}/\wc{048}).
  \item \textbf{\wc{013}.} The API secret is still written to \texttt{localStorage} at 18 sites. Any
        cross-site scripting on the domain exfiltrates a long-lived credential.
  \item \textbf{\wc{004}.} 28 \texttt{.env} files remain committed.
  \item \textbf{\wc{109}.} \texttt{dashboard.get\_invoice\_count} returns a global financial total with
        no scoping; any account sees organisation-wide figures.
  \item \textbf{\wc{121} / \wc{112} / \wc{023}.} ``Config/Deployment'' is a fair label, but all three are
        still live on \texttt{api-dev}: CORS reflects any origin with credentials, no security headers
        are sent, and tracebacks appear in error bodies. The label is accepted; closure is not.
\end{itemize}

\section{Reclassifications accepted}
The ``Config/Deployment'' framing is accepted for the concurrency, CORS, header, traceback and session
items; they are deployment configuration, not code defects, and still need resolving. The
``Documentation/Handover'' framing is accepted for the permission-model-in-no-repository, runtime-config
and fresh-install items. \wc{009}, \wc{117}, \wc{002}, \wc{092} and \wc{104} are accepted as non-bugs
or by-design. \wc{068} is a fair partial downgrade. Genuine fixes confirmed: the auth guard (\wc{011}),
the stored-HTML sink (\wc{130}), the cross-centre invoice for ordinary accounts (\wc{095}, \wc{085}),
mass assignment (\wc{122}, now 23 of 28 sites guarded), the navigation list structure (\wc{027}, by axe),
and \wc{018}, \wc{041}, \wc{010}, \wc{005}, \wc{006}, \wc{007}, \wc{014}.

\section{Severity}
Only one downgrade is contested on risk grounds. \textbf{\wc{048}} (S1$\rightarrow$S3): the stated
reason, ``bypass only for Administrator,'' is inaccurate --- the gate is still \texttt{System Manager}.
The disclosure is scoped for ordinary accounts (all six persona accounts confirmed non-\texttt{System
Manager}), but the bypass remains reachable by any \texttt{System Manager} account on youth counselling
data. Recommended severity S2. Two further downgrades are noted without a hard objection: \wc{013}
(credential exposure, rated S2 here) and \wc{126} (uncontrolled financial-state transitions). The other
23 downgrades are accepted.
